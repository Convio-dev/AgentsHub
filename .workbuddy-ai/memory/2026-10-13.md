# 2026-10-13

## Project review — Agents Hub / HermesHub

Analyzed the full codebase (~21.6k LOC, .NET 10 WinForms + WebView2, single-file portable exe).

### Architecture map
`Program.cs` (single-instance mutex + show-window event) → `MainForm` (WebView2 host + tray icon, no WinForms controls) → `ui/index.html` dashboard (9 tabs) ↔ `DashboardWebBridge` (~60 JSON actions in, ~20 push events out, postMessage RPC) → services → external CLI processes.

Services: `CliManagerService` (ConPTY sessions, ports 9119/9229/9339), `HermesProcessService`, `LanProxyService` (0.0.0.0:9191 → 127.0.0.1:9119 TCP proxy), `OpenCodeWatcherService` (sidecar + SSE), `ClaudeOpenRouterProxyService` (Anthropic→OpenAI translation on 127.0.0.1:9230), `AntigravityProfileService` (multi-account via Win32 Credential Manager), `AiConfigService` (%AppData%\AgentsHub\ai_config.json), `PromptEnhancerService`, `ProtonVpnService`, `CliWebTerminalServer`.
Helpers: `NetworkHelper`, `StartupHelper` (HKCU\Software\AgentsHub), `ThemeManager`, `QrCodeHelper`, `ShellLauncher`.
External: hermes dashboard, claude, agy, OpenCode sidecar, OpenRouter, LAN devices.

### Verified findings
- `build-installer.cmd` invokes `ISCC.exe HermesHub.iss` but only `AgentsHub.iss` exists → installer build is broken.
- `Helpers/FirewallHelper.cs` has 0 external references (dead), yet README still advertises the firewall feature.
- `PromptEnhancerForm.cs` never instantiated; `SettingsForm.cs` only reachable from it → both dead code. Dashboard + bridge replaced them.
- `assets/web/*` is a stale near-duplicate of `ui/*`; only `ui/` is loaded (assets/web used only as a fallback for `hermes-offline.html`). `HermesHub.csproj` copies both.
- `ui/tabs/*.html` and `ui/modals/add-profile.html` are never referenced (dead leftovers from a split-file design).
- README is stale: claims v1.0.2, lists only 2 services, wrong project structure. Actual version 1.0.3.
- Version string "1.0.3" hardcoded in ≥6 places (bridge, index.html, dashboard.js ×2, logs.html, assets copies).
- 101 silent `catch {}` blocks across .cs files.
- `Controls/` folder is empty; `Profiles/` empty at rest.

### antislop
Mode unresolved — no global preference at `%APPDATA%\antislop\settings.json`. Asked the user for mode before giving UI/UX enhancement recommendations.

## Implemented: Terminal workspace empty state + 3 preset configurations

### Changed files
- `Services/AiConfigService.cs` — added `TerminalWorkspacePreset` to `AiConfig`; added `NormalizeWorkspacePreset`, `ApplyWorkspacePreset`, `GetTerminalWorkspacePreset`, `ApplyWorkspacePresetFlags`, `SetWorkspaceEnabled`, `IsWorkspaceEnabled`, `MatchPresetToFlags`. `EnsureDefaults` now applies the preset flags when the config has no workspaces yet (fresh install), and otherwise re-derives the label from the actual flags so it can never advertise a preset the workspace is not in. `SaveConfig` preserves the stored label when a payload omits it.
- `CliWebviewForm.cs` — **removed the forced `ToggleCliWorkspace("hermes", true)` fallback** in `RebuildTabs`. When nothing is enabled it now clears `_activeTabId`, hides the CLI action buttons via a new guard at the top of `UpdateToolbarUi`, hides all terminal WebViews, and shows a themed `_emptyStatePanel` (title/subtitle/dropdown/"+ Add to Workspace"/hint) with `EnsureEmptyStatePanel`, `LayoutEmptyState`, `PopulateEmptyStateCombo`, `EmptyStateAddButton_Click`, `ApplyEmptyStateTheme` and a private `EmptyStateOption` type. Adding a workspace persists it, rebuilds tabs, switches to it, and starts the process.
- `Services/DashboardWebBridge.cs` — added `apply_terminal_preset` (applies the preset and calls `CliWebviewForm.RebuildTabs()` when the window is open) and `get_terminal_preset`. `GetAiConfigDto` now also emits `terminalWorkspacePreset` **and `cliWorkspaces`**.
- `ui/index.html` — added the `#terminal-presets-group` switcher bar (Clean Slate / AI Duo / Full Suite) + `#preset-active-label` above the terminal tabs.
- `ui/js/dashboard.js` — added `TERMINAL_PRESET_LABELS`, `renderTerminalPresetState`, `loadTerminalPreset`, `setupTerminalPresets` (registered as `TerminalPresets` in `initSteps`).
- `ui/css/dashboard.css` — added `.terminal-preset-bar` + `.preset-btn.active`; `#terminals-view` height reduced to `calc(100vh - 136px)` to make room for the bar.

### Bug found and fixed along the way
`GetAiConfigDto()` never included `cliWorkspaces`, but `save_ai_config` **replaces the whole config**. So any dashboard config save (e.g. editing a provider) silently dropped every CLI workspace, including user-added ones. Fixed by adding `cliWorkspaces` to the DTO. The same class of bug still affects the Claude gateway fields (`ClaudeEngineMode`, `ClaudeSelectedModel`, `ClaudeCustomGatewayUrl`, `ClaudeInjectionEnabled`, `ClaudeSelectedGatewayId`, `ClaudeGatewayProviders`) — still missing from the DTO, not fixed.

### Verification

- Throwaway harness, 27 assertions, all passing: preset normalisation, Clean/Duo/All flag outcomes, unknown-preset fallback, label round-trip, `cliWorkspaces` round-trip, and label self-correction across simulated restarts (All/Duo/Clean/custom-mix). The real `%AppData%\AgentsHub\ai_config.json` was backed up and restored around the run and verified intact (9858 bytes, 5 providers, 6 shortcuts, 2 gateways, 3 workspaces).

## Implemented: terminal top-clipping fix + tab right-click context menu

### Changed files
- `ui/terminal.html` **and** `assets/web/terminal.html` — `#terminal-container` padding `10px 14px 10px 14px` → `18px 16px 12px 16px`; `reportResize()` now clamps the viewport (`viewportY < 0` → `scrollToTop()`, `>= baseY` → `scrollToBottom()`) so a refit can never leave the first line above the viewport. The two files remain identical apart from their asset paths (`./css/`, `./js/` vs flat).
- `CliWebviewForm.cs` — `contentPanel.Padding` set to `new Padding(0, 10, 0, 0)` in both places (toolbar setup and `ApplyTheme`). Added `_tabContextMenu` field, `ShowTabContextMenu`, `LaunchExternalCmdForTab`, `HandleRenameTabAsync`, `HandleDeleteTabAsync`, `PromptForName` (a small themed input dialog). `AddTabButton` now hooks `MouseDown` for `MouseButtons.Right`.
- `CliWebviewForm.Designer.cs` — `Dispose` releases `_tabContextMenu`.
- `Services/CliManagerService.cs` — added the `ExternalLaunchSpec` type and `BuildExternalLaunchSpec(string id)`, which mirrors the embedded-session rules: agy profile → `agy` in the profile's VirtualHome with USERPROFILE/HOME/APPDATA/LOCALAPPDATA/PORT/ANTIGRAVITY_PORT; claude_code → `claude` with ANTHROPIC_BASE_URL/AUTH_TOKEN/MODEL/DEFAULT_OPUS_MODEL (and starts the local proxy when the active gateway is `preset_local_proxy`); hermes → `hermes dashboard --port N`; otherwise the workspace's configured command + working directory.

### Design decisions
- **Env building lives in `CliManagerService`, not the form** — it owns process/env concerns and already holds the profile service and proxy. `Start(id)` was left untouched to avoid regressing the embedded-session path.
- **"Remove / Close Tab" does not delete workspace config.** Built-in/custom workspace tabs are stopped and disabled (re-addable from Manage CLIs). Only Antigravity profile tabs are actually deleted, behind an explicit warning, because an agy tab exists solely because the profile exists.
- Rename is disabled for built-in CLIs (fixed ids); enabled for agy profiles (`ProfileService.RenameProfile`) and custom workspaces (`SaveCliWorkspace`).

### Verification
- `dotnet build -c Release` → 0 errors, 0 warnings (an intermediate Debug build caught a real `CS0103` — `NormalizeCliId` needed qualifying as `AiConfigService.NormalizeCliId`).
- Throwaway harness, 26 assertions, all passing: null/empty id, hermes command + workdir, claude command/workdir/env keys (no ANTHROPIC_API_KEY injected), custom workspace command/workdir, unknown-id fallback, and the agy VirtualHome env. Probe profile directory removed and the real config restored afterwards (verified 0 entries left in `Profiles/Antigravity`).
